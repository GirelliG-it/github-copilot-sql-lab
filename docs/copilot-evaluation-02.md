## Experimental requirement

A valid period consists of a four-digit year, one space, a quarter label from 1e through 4e, one space, and lowercase kwartaal, optionally followed by one asterisk. No other characters are permitted.

This is an experimental requirement, not a verified contract for all CBS data.

## Copilot assessment

Copilot predicted that the current query would include three invalid labels:

- geen kwartaal
- 2023 5e kwartaal
- 2023 1e kwartaal extra

It concluded that substring matching does not enforce the complete required format.

## Independent validation

I added a separate test with two input rows:

- ('2023 1e kwartaal', 100)
- ('2023 5e kwartaal', 999)

The expected result contained only the first-quarter row.

The unchanged query returned both rows. The new test failed because the fifth-quarter row was incorrectly included.

## Finding and limitations

Execution supports Copilot’s prediction for the invalid fifth-quarter example.

The other two misleading labels have not yet been independently tested. This result does not establish correctness across all possible period labels or overall Copilot assessment accuracy.

## Original prompt
  
  Assess this DuckDB SQL query without executing code, changing files, or inspecting repository files. Use only the information   below.
  
  SELECT *
  FROM cargo
  WHERE Perioden LIKE '%kwartaal%';
  
  The cargo table has two columns:
  - Perioden VARCHAR
  - weight BIGINT
  
  For this experiment, a valid quarterly period must have exactly:
  - A four-digit year.
  - One space.
  - A quarter label: 1e, 2e, 3e, or 4e.
  - One space.
  - The lowercase word kwartaal.
  - Optionally, one trailing asterisk (\*).
  - No other characters.
  
  This is an experimental requirement, not a claim about all CBS data.
  
  Assess these input values:
  - 2023 1e kwartaal
  - 2023 4e kwartaal*
  - 2023*
  - NULL (a SQL missing value, not the text "NULL")
  - geen kwartaal
  - 2023 5e kwartaal
  - 2023 1e kwartaal extra
  
  For each value, show:
  1. Whether the current query would include it.
  2. Whether the requirement permits it.
  3. Whether those results agree.

Explain any mismatches and whether the query meets the requirements. Distinguish reasoning from execution evidence. Do not propose a replacement query yet.

## Explanation
  
  The predicate is:
  
  ```sql
  Perioden LIKE '%kwartaal%'
  ```
  
  It matches any non-`NULL` value containing the lowercase substring `kwartaal` anywhere.
  
  Therefore:
  
  - Valid quarterly values containing `kwartaal` are included.
  - `2023*` does not contain `kwartaal`, so it is excluded.
  - `NULL` produces an unknown result for the `LIKE` predicate. The `WHERE` clause retains only rows where the predicate is true, so the `NULL` row is excluded.
  - `geen kwartaal` contains `kwartaal`, despite not having the required year, quarter label, spacing, or structure.
  - `2023 5e kwartaal` contains `kwartaal`, but `5e` is not an allowed quarter label.
  - `2023 1e kwartaal extra` contains a valid-looking prefix but has additional trailing characters, which the requirement forbids.

Conclusion

The query does **not** meet the stated requirement. It agrees for the two valid examples and for the two values that do not contain `kwartaal`, but it incorrectly includes three invalid values because it checks only for substring presence rather than the complete required format.
